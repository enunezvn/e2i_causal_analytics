# 21-Agent Audit — Findings & Remediation Plan (2026-06-09)

**Type:** audit-only (no code changed). **Method:** layered, OOM-safe, adversarial. **Scope:** all 21 production agents × 4 dimensions (functional / wiring / data-substrate / OOM).
**Design:** `docs/plans/21-agent-audit-design-20260609.md` · **Plan:** `docs/plans/21-agent-audit-implementation-20260609.md` · **Repro/raw:** `docs/reports/21-agent-audit-20260609-repro/`

## 1. Executive summary

Of 21 agents, **2 are clean** (`scope_definer`, `explainer`); **19 carry findings** (20 findings total). Severity: **1 CRITICAL, 8 HIGH, 9 MEDIUM, 2 LOW.** Every finding was independently source-verified; none was refuted (11 CONFIRMED, 9 PARTIAL — "partial" = real but narrower/wider than first claimed).

**The headline reframe:** the prod database is **not** empty — it holds real data (10,040 treatment_events, 5,313 observability spans, 4,667 business_metrics, 2,702 patient_journeys, 621 experiments). The problem is the opposite of starvation: **several agents fabricate, launder, or crash instead of using the real data that is sitting right there.** `observability_connector` serves mock metrics while 5,313 real spans exist; `experiment_monitor` reports "0 experiments checked" while 621 run; `gap_analyzer` crashes on 4,667 real metric rows and reports "no gaps" as HTTP 200; `health_score` shows an invariant 100/grade-A on the live dashboard tagged `data_provenance='measured'`.

**The systemic root cause** behind the most dangerous findings is a recurring **"graceful degradation that fails OPEN"** pattern: when a real backend is missing or a call fails, the code falls back to a simulated/mock value **and reports `success=True` / `MEASURED` / grade-A** instead of failing closed. This is the same class of defect across `health_score`, `model_deployer`, `tool_composer`, `observability_connector`, and `feature_analyzer`. A second systemic theme is **incomplete dispatcher input-bridging**: the `#260` `input_model`/`_coerce` pattern that lets the orchestrator supply an agent's required args was applied to some agents but not all, leaving a cluster of Tier-2/4 agents unreachable via chat (they fail closed — safe, but the feature is dead).

5. **Security:** Supabase flagged **73 tables with RLS disabled** (see §6). Separate from the agent audit but surfaced here per the advisory.

## 4. Findings detail

Each finding states the REASON-BEFORE-RULES intent (is the mock a legitimate scaffold or a real defect?) so remediation targets the *functional* problem, not a relabel.

### 🔴 CRITICAL

**F1 — health_score: live dashboard shows invariant 100/grade-A, tagged `measured`.** CONFIRMED. User-facing, fails OPEN.
The mocks (`component_health.py:83 _create_mock_status`, empty-collection `=1.0` defaults in model/pipeline/agent_health) are **legitimate test scaffolds**. The defect is **production wiring**: the route at `routes/health_score.py:789` constructs `HealthScoreAgent()` with all stores `None`, so every dimension defaults to 1.0 → composer (weights sum 1.0) → 100.0/grade-A, *always*. A real `SupabaseHealthClient` was purpose-built (`health_client.py`, docstring: "replaces the mock fallback … when no health_client is injected") but is never injected. Separately (**F1b**, HIGH) the REST `/components,/models,/pipelines,/agents` return hardcoded mock (`_get_mock_*_health()`, e.g. `accuracy=0.89, auc_roc=0.92`) while `_resolve_health_provenance` tags the response `DataProvenance.MEASURED` merely because the agent *imports*. SystemHealth.tsx renders these as real with no provenance banner.
**Fix:** inject the real client/stores at the route; make each node **fail-closed** (degraded/unknown, not 1.0) on absent store; only return MEASURED when the agent's real `check_health()` output is actually used.

### 🟠 HIGH

**F2 — gap_analyzer: KeyError laundered into "no gaps", HTTP 200.** PARTIAL (core holds). User-facing, fails OPEN.
Real path crashes (segment-column mismatch) over **4,667 real `business_metrics` rows** (the table *does* have a `region` column — the connector frame is the problem), the broad `except` swallows it, downstream empty-branches + the formatter overwrite `status` `failed`→`completed`, and `gaps.py:663-666` maps to HTTP 200 "No significant performance gaps." Production path (not a scaffold). **Fix:** preserve terminal-failure status in the empty-input branches (`roi_calculator.py:106`, `prioritizer.py:65`) and set `AnalysisStatus.FAILED` when `errors` is non-empty rather than keying only on `status=='completed'`.

**F3 — observability_connector: serves fabricated metrics while 5,313 real spans exist.** PARTIAL. Fails OPEN (not yet user-consumed → HARMFUL-on-exposure).
The `_get_mock_spans` fallback is an intentional Phase-2 scaffold (docstring "Fallback to mock data when repository unavailable"). The defect is a **constructor kwarg bug**: the repo is built with a wrong `client=` kwarg → TypeError → swallowed → mock path taken 100% of the time, even though `ml_observability_spans` holds 5,313 real rows. **Fix:** pass the correct `supabase_client=` kwarg at `metrics_aggregator.py:30` + `agent.py:91`.

**F4 — model_deployer: fabricates `success=True`/version=1, writes no rows.** CONFIRMED. Fails OPEN.
"Graceful degradation (try real API, fall back to simulation)" is a documented pattern (commit 214890aa), but it returns `registration_successful/promotion_successful=True` with `model_version=1` when MLflow fails (default `model_uri='simulated://model'` guarantees failure), fabricates a random-uuid rollback id, and `_store_to_database` short-circuits → `ml_deployments`/`ml_model_registry` stay at **0 rows** despite `status='completed'`. **Fix:** set `*_successful=False` on simulated/failed registration and surface it into status + audit `validation_passed`.

**F5 — orchestrator: fabricates ATE=0.12/$2.5M for a missing agent (live on main).** CONFIRMED. User-facing, fails OPEN.
`_mock_agent_execution` is a legitimate test scaffold; the defect is it's **reachable unguarded in a degraded/partial registry** (`create_agent_registry(fail_on_import_error=False)` silently drops un-instantiable agents), fabricating plausible analytics as `success=True`. **Fix:** merge #814 (`a7fa162d`) to main — keyword-only `allow_mock=False`, fail closed on missing agent.

**F6 — tool_composer: `success=True` when 0/N tools succeed (live on main).** CONFIRMED. User-facing, fails OPEN.
Despite #813's "honest tools," the BUILD-RESULT block still maps to `success=True` and synthesizes a ~0.8-confidence answer with no anti-fabrication guard when all tool outputs FAILED. **Fix:** gate on `tools_succeeded==0` → `status=FAILED, success=False`; add a no-fabrication instruction to the synthesis system prompt.

**F7 — experiment_monitor: "0 experiments checked" while 621 run.** CONFIRMED. Fails CLOSED (degenerate-empty, not fabricated).
Every DB node does `await get_supabase_client()` — but that factory is **synchronous** → TypeError on every call → terminal computes over empty state. A genuine copy-of-wrong-symbol bug (an async `get_async_supabase_client()` exists). **Fix:** await the async factory in the four nodes.

**F8 — feature_analyzer: silent np.random SHAP background.** CONFIRMED. Fails OPEN.
When `X_sample` is absent, SHAP silently uses an `np.random` synthetic background (intentional stopgap per comment "In production, this would come from Feast"), and the full graph never bridges `X_train_selected` into SHAP. Importances can be synthetic and unlabeled. **Fix:** fail-closed skip when no real sample; bridge `X_train_selected`; gate synthetic background behind a flag that stamps `data_provenance='synthetic'`.

### 🟡 MEDIUM

**F9 — model_selector** (CONFIRMED): `MLDataLoader.execute_query` does not exist → AttributeError silenced (`type:ignore` + bare except) → ~40% of the selection score is a frozen constant; author intended real history (commit 209f9cff). **Fix:** implement `execute_query`; remove the `type:ignore`; log the swallowed error.
**F10 — experiment_designer** (PARTIAL): `MockKnowledgeStore` (unmarked, non-flag-gated) seeds the design LLM prompt with fabricated org context on every prod run; a scaffold its own docstring says to replace. **Fix:** real/empty context, not silent mock.
**F11 — drift_monitor** (PARTIAL): the V4.4 `structural_drift` node writes results but the input plumbing + `alert_aggregator` drop them, so DAG drift can read 0.0/"NO DRIFT". Fails closed (understated). **Fix:** thread DAG fields into input + fold `structural_drift_results` into the aggregator/summary.
**F12–F14 — dispatch-reachability cluster** (heterogeneous_optimizer CONFIRMED, prediction_synthesizer PARTIAL, resource_optimizer CONFIRMED): the dispatcher calls each agent's real entry-point but supplies no inputs for agents lacking an `input_model` bridge → ValueError/TypeError → **fail closed (honest, no fabrication)**; feature dead via chat (works via REST/tier-0). Same root as the #260 `_coerce_to_input_model` pattern, just not applied to these. **Fix:** add `input_model`/`_coerce` defaults (or a dispatcher special-case mirroring `_resolve_tool_composer_data`) for these agents.
**F15 — feedback_learner** (CONFIRMED, *known*): constructed with empty `feedback_store`/`knowledge_stores={}` in all prod sites → `update_effectiveness` pinned 0.0; documented starved state ([[dspy_loop_starved_no_fuel_20260608]]). **Fix:** construct with a real feedback source + `focus_agents`.
**F16 — data_preparer** (PARTIAL): `data_loader.py:196` uses `DataFrame.append` (removed in pandas 2.x; repo pins 2.3.3) → crash on the Supabase entity-split path. Fails closed. **Fix:** `pd.concat([...], ignore_index=True)`.
**F17 — cohort_constructor** (PARTIAL): `tier0_integration.py:24` (and `:471`) `from cohort_constructor import …` targets a non-existent top-level package → ModuleNotFoundError on the `data_source` branch (reorg artifact). + iterrows OOM at 100K. **Fix:** `from src.agents.cohort_constructor import …`.

### ⚪ LOW

**F18 — causal_impact** (PARTIAL): orchestrator route fails closed (ValueError) because causal inputs aren't supplied — **correct, safe behavior**; only a feature-completeness gap. (The cited `router.py:40-48` was wrong; validation is `agent.py:177-181`.) No fix needed to be *safe*; bridge inputs only if chat-routing is desired.
**F19 — model_trainer** (PARTIAL): intentional 5-fold CV + 200-perm + 1000-bootstrap with no in-agent thread cap → the observed 5.9 GB spike, mitigated only by external `LOKY_MAX_CPU_COUNT=1`. No user-facing harm. **Fix:** wrap per-fold refit in `threadpoolctl.threadpool_limits(1)` + clone with `n_jobs=1`.

## 6. Security finding (surfaced by Supabase advisory)

**73 public tables have Row-Level Security DISABLED** on the prod DB — "anyone with the anon key can read or modify every row." Because the React frontend ships a Supabase anon key to browsers, this is a real read/write exposure of all analytics, patient_journeys, treatment_events, and audit tables. **Do not blindly enable RLS** (enabling without policies blocks all access). Decide per-table whether the anon role should reach it and add policies; the full `ALTER TABLE … ENABLE ROW LEVEL SECURITY` list is in the repro dir / Supabase advisory. Treat as a separate security workstream.
