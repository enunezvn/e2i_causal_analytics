# Codex audit — iteration 7 — issue #1775, PR #1776 (head 4ec918230)

## What this branch does

Grounds the causal-analysis clinical-context panel in the SCENARIO being analysed.
Before: the panel showed accurate indication/mechanism/RWE facts that were the same
regardless of which outcome the causal analysis was estimating. Now it also returns
`analysis_grounding` — verbatim FDA-label considerations, selected by relevance to
the analysed outcome, with a note explaining the tie to the commercial question.

Zero new upstream calls: the openFDA label is ALREADY fetched for the indications
fragment; this branch parses more out of the same payload.

   Construct label text that makes the cursor walk emit a title or detail containing
   words from a different bullet, or a `references` string that does not belong to
   the emitted body. This is the only defect class that matters here — a missed
   bullet is acceptable, a mis-cited one is not. Note that `_swallowed_a_boundary`
   now backstops the heuristic: to demonstrate a merge you must get past BOTH.
6. **Is the UNDECIDABLE claim wrong?** I assert that a prose list marker `(2)` inside
   section 2 cannot be distinguished from a real terminal `( 2 )`. If there IS a
   discriminator that does not cost real bullets, that is a HIGH finding — I would be
   documenting a residual I could have fixed.
7. **Do the bullet-glyph and header-period fixes break anything?** `_BULLET_GLYPHS`
   widened the boundary rule and `lstrip` now strips leading glyphs; the header strip
   now allows `[.:]`. Find a real SPL shape where either loses or corrupts content.
8. **Is the 16-label audit itself sound?** It checks verbatim membership, reference
   adjacency over EVERY occurrence, and header leakage. What defect would it miss?
2. **Can a full prescribing-text body leak into a Highlights item?** The Highlights
   region ends at the first `N.N Title` subsection; check that boundary.
3. **`ground_analysis` relevance selection**: can an outcome select a label
   consideration that does not bear on it, or can the NOTE claim something the
   selected considerations do not support? Check every outcome constant against
   `_PERSISTENCE_OUTCOMES` / `_INITIATION_OUTCOMES` and the unrecognised-outcome path.
4. **Honesty of the no-match path**: when nothing is selected, does the panel copy
   claim more than "we found nothing in the label that bears on this"?
5. **Test vacuity**: does any test pass for a reason other than the one it names?
   (Round 1 caught one of mine where the fixture detail contained the phrase the
   test asserted was absent.)
