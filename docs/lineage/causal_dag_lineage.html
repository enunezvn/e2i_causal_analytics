Lineage document · inputs → construction → outcome → governance

How a causal DAG is built, and what is allowed to change it

The platform never asks a language model to draw a causal graph. Every edge in a shipped DAG comes from one of four places: a column allowlist a maintainer wrote, a covariate the caller declared, the estimand under test, or a constraint-based structure-learning run on the actual estimation frame that survived a corroboration gate. This page traces that lineage in the order the code executes it, and names every threshold, every override, and every place a human can intervene.

Primary path: POST /causal/agent-analyze → the causal_impact LangGraph → GraphBuilderNode. Secondary paths (the tool registry's discover_dag, the feature analyzer's causal ranker, the multi-library pipeline's NetworkX executor) are called out where they diverge. Read left to right on the map, or jump by stage.

1Inputs

Two kinds of things enter DAG construction: a numeric estimation frame, and declared knowledge about the roles of its columns. Both are gated by allowlists that a maintainer wrote. Nothing enters from free text.

1.1 Entry points

1.3 The frame loader, step by step

Everything below happens in _load_agent_estimation_frame before the agent sees a single row. Each step either fails closed with an HTTP error or leaves an observable trace; none fabricates a row. causal.py:3014

  1. Route by grain. hcp_adoption always, and nba_triggers whenever a patient-joined column is requested, go to join-aware loaders with the same allowlist gate.
  2. Allowlist check. Requested treatment, outcome, and covariates must be in the union of the spec's role lists (400 otherwise). A covariate must additionally hold the covariate role (_require_covariate_role).
  3. Brand as filter, not variable. brand scopes rows and is never a column in the frame.
  4. Provenance filter. apply_provenance_filter includes or excludes is_synthetic rows according to the deployment; the tag itself is dropped before any estimator via PROVENANCE_DROP_COLS. src/repositories/provenance.py:19
  5. Row coercion. Rows missing a treatment or outcome value are dropped. Numeric derivations turn text or continuous axes into 0/1 contrasts: complement_inhibitor_status → prior C5 exposure, disease_stage → advanced line, urticaria_severity_uas7 → uncontrolled CSU (≥ 28). causal.py:1251
  6. Empty result fails closed. No usable rows is a 503, not an empty frame.
  7. All-NULL covariate drop (see 1.2).
  8. One-hot encoding. geographic_region becomes geographic_region=<level> float dummies, sorted levels, first level dropped as reference. The DAG's node names are these dummy names. causal.py:2762
  9. Row cap. Request default 1500, bounds 100–20000. The leaderboard uses 5000 because measured medium-severity effects fail the refutation gate at 1500 and pass at 5000. src/api/schemas/causal.py:501 causal.py:1030

The loaded frame is placed at state["data_cache"]["estimation_data"]. This exact key matters: the graph builder previously read a key that was always None for real callers, which silently disabled discovery on every production run until it was fixed. graph_builder.py:757

1.4 Declared knowledge

Four things are asserted rather than learned. They are the ochre edges on the map.

Two confounder channels modeled_confounders vs anchored_confounders

The API seeds the state with the same covariate list in two keys that mean different things. causal.py:3366

modeled_confounders
Adjustment-guarantee channel. Every name here is unioned into the final adjustment set regardless of what the DAG shows. It forces no DAG edge.
anchored_confounders
Structural-prior channel. When the key is present, exactly these names become required conf→T and conf→Y edges for guided discovery. The API passes an empty list, so in production only the estimand edge is prior-required and the data selects the confounder edges.
confounders
Legacy single channel. When anchored_confounders is absent, the builder falls back to anchoring modeled_confounders, then confounders, so pre-split callers keep their old shape. graph_builder.py:604
Measured, recorded in the source

Declaring every covariate as a required edge produced a DAG that was identical for real data and pure noise (F1 0.78, SHD 4 on the recovery benchmark). Empty anchors give F1 mean 0.93 and SHD ≤ 1 at n = 2000, and let the gate score real bootstrap evidence instead of a prior-determined renormalisation.

Design declaration randomized_design

_is_randomized_treatment(dataset, treatment_var) reads the spec's per-treatment list. True only for nba_triggers.control_group_flag. It is never inferred from an empty discovered backdoor. Effects downstream: default covariates become empty, the E-value sensitivity test is marked not applicable instead of blocking, and the narrative stops calling an RCT observational. causal.py:1036 3233

Hard-coded domain edges KNOWN_CAUSAL_RELATIONSHIPS, 13 edges

A set of pharma-commercial edges such as marketing_spend → hcp_engagement_level and formulary_status → prescription_volume. An edge is added only when both endpoints are already nodes, so on the real dataset schemas above it is a no-op: none of those names occur in patient_journeys. It matters for the keyword-inferred path below. graph_builder.py:57 413

Keyword inference of T and Y only when the caller supplied neither

_infer_variables_from_query matches six treatment keywords and six outcome keywords and defaults to hcp_engagement_level → patient_conversion_rate. The estimation node refuses to run when the treatment or outcome is not a frame column, precisely so this default can never silently estimate against the wrong positional columns. graph_builder.py:312 estimation.py:744

Structural priors for the learner CausalPriorKnowledge

The only prior-edge channel into structure learning has three fields: tiers (an earlier tier cannot be caused by a later one), required_edges, and forbidden_edges. The graph builder is the sole producer. It sets tiers = [[all covariates], [T], [Y]] and required_edges = [(T, Y)] + anchored pairs. 1.6 The feature causal-role system

A separate, older subsystem classifies individual features into Pearl roles (ancestor, confounder, instrument, mediator, collider, descendant) for the ML data-preparer. It is the intended source of role_attributions, which the adjustment-set policy node (section 4.1) would consume. Its lineage is worth knowing because it is the only place a language model touches causal structure, and even there the model is audit-only by default.

Layer 1 · Feature contracts and manifests declared temporal semantics; one manifest attests edges

FeatureContract records when a feature is knowable (index_date, enrollment, post_index plus an offset), its source, aggregation, and window. Six manifests exist (csu 28, optum 63, optum_mart 80, optum_hcp 35, synthetic 2, synthetic_csu 4 contracts). Post-index features are mechanically forbidden. src/data/feature_contract.py:182 src/data/manifests/__init__.py:88

CausalStructureAttestation lets an author write edges, never a role: the role is derived from the edges by extract_role. Only the Optum manifest supplies attestations: 17 named instrument features get (f→T), (T→Y); every other pre-index feature gets (f→T), (f→Y), (T→Y) and derives as a confounder. No manifest declares causal_role= directly. optum_feature_manifest.py:784 src/ml/causal_role_dgp/extractor.py:91

Layers 2–4 · KG signal, adversarial leakage, DSPy classifier and the ensemble voter that combines them

Layer 3 is a permutation test of single-feature AUC with a joint rule: severity is high only when z > 5.0 and |ΔAUC| > 0.10 (calibrated 2026-05-14, measured 0% FPR / 100% TPR). Layer 2 queries a committed knowledge-graph cache (UMLS, RxNav, Open Targets) and is bound to exactly one cohort, optum, in shadow mode against one target code. Layer 4 is a DSPy chain-of-thought classifier compiled from a 240-example set into 192 bootstrapped demos. src/agents/ml_foundation/data_preparer/nodes/adaptive_validity_check.py:400 src/data/kg/activation.py:78 src/data/causal_role_classifier.py:241

The voter's precedence is fixed: Layer 1 high veto → adversarial high veto → structural (attested) role → abstain on KG/LLM contradiction → LLM (only if ADAPTIVE_LAYER4_LLM_DECIDES=1, default off) → KG only → adversarial moderate → abstain. Role-to-remediation is asymmetric on purpose: a collider may only be dropped, never windowed or transformed. src/data/kg/ensemble_voter.py:122 664

Finding

No producer populates state["role_attributions"] for the causal_impact agent on the API path. The dispatcher now passes the key through on the explicit-spec branch, as it already did for the heterogeneous optimizer, so a caller that supplies attributions reaches the policy node (issue #1976). Combined with the policy's default of OFF, the feature-role system still has no effect on the estimation DAG unless both are set.

1.7 What is not an input

  • The ontology. src/ontology and config/ontology/*.yaml define a FalkorDB schema with a CAUSES edge type and confidence thresholds (proceed ≥ 0.75, review ≥ 0.50), but no module under src/causal_engine or the graph builder imports it. It represents already-discovered paths; it does not seed them.
  • An LLM edge proposer. CausalGraphSignature is defined in dspy_integration.py:225 and has zero call sites; its docstring now records it as a deliberate roadmap placeholder (issue #1973). The DSPy module that is wired consumes estimation and refutation text for narrative, not structure.
  • forbidden_edges. Declared, translated, hashed, never set by the agent path. Kept as API surface for callers that must veto an edge; documented as such (issue #1973).
  • The discovery cache. DiscoveryCache (Redis, 1 h TTL) has no production caller. Every run re-learns from scratch, including the 20 bootstrap resamples. Its module docstring now lists the two prerequisites before it could be wired: the serializer drops ensemble_dag, and object-dtype frames bypass the hash rounding contract (issue #1973).
  • config/agent_config.yaml. Its require_dag_approval: true and gate thresholds are not read by any Python module. The block is now annotated as documentation-only and its numbers mirror the live class constants cited in sections 2.5 and 4.2 (issue #1975).

2Construction

One node, GraphBuilderNode.execute, owns the DAG. It decides whether to learn structure, learns it under priors, scores the evidence, merges the result with a manual graph under explicit override rules, computes the adjustment set, labels each edge with why it exists, and hashes the structure. Performance targets stated in the docstring: under 10 s manual, under 30 s with discovery.

2.1 Where it runs

audit_init → graph_builder → adjustment_set_policy → estimation
          → [refutation | error_handler] → [sensitivity | error_handler]
          → interpretation → END

The graph is compiled with checkpointer=False on purpose: it runs as a subgraph of the chatbot graph, and a parent Redis checkpointer would try to serialise the DataFrame in state. Each node is wrapped in an Opik span and an audit-chain entry. src/agents/causal_impact/graph.py:462 542

The state contract that matters here: warnings and errors are append-only accumulators, so every node returns only its new entries via spread_safe(state). The builder uses this to surface a skipped discovery as a warning the API echoes. state.py:216

2.2 The decision to discover

  1. auto_discover on state? Default False in the node; the API request schema defaults it to True. Off means the manual DAG only.
  2. data_cache["estimation_data"] present? Missing raises a distinct error that the node catches and records as discovery_skip_reason plus a warning. The run degrades to the manual DAG and says so.
  3. discovery_guided and both T and Y are frame columns? Yes → guided single-algorithm PC. No → the legacy unguided GES + PC ensemble with bootstrap off and the latent diagnostic off.

Each algorithm is bounded by the runner's timeout_seconds (default 300). Ensemble voting and cycle removal _build_ensemble, _remove_cycles
n_converged = converged algorithms only
min_votes   = max(1, int(n_converged * ensemble_threshold))
confidence  = n_votes / n_converged          # denominator is converged, not attempted

Then _remove_cycles repeatedly finds a cycle and drops its lowest-confidence edge until none remain. This is the only acyclicity guarantee in the system; the gate does not re-check, and the former inert require_dag flag was deleted as false assurance. runner.py:579 804 gate.py:44

Bootstrap edge stability the corroboration signal for a single-algorithm run

Runs only when bootstrap_resamples > 0, exactly one algorithm converged, and edges exist. Resamples rows with replacement (seed 42), re-runs the algorithm, and sets bootstrap_stability = recovered / succeeded per edge, overwriting the vacuous confidence = 1.0. If fewer than max(2, n // 2) resamples succeed the stability is None and the gate treats the run as uncorroborated. runner.py:662 712

FCI latent-confounding diagnostic annotates, never gates

A second, unguided FCI run (priors stripped, no bootstrap) reports bidirected edges, the PAG signature of an unmeasured common cause. The builder sets flag = True only when the estimand pair itself is bidirected. Measured on the platform's binary-logit frames: 10/10 detection on a null-effect latent DGP at n = 2000, 0/10 false alarms on observed-confounder and noise controls; covariate bidirected pairs are false alarms on every control and stay in the payload as data only. The interpretation node surfaces the warning only when the E-value corroborates fragility, or fails open on a terminal path where it cannot check. runner.py:734 graph_builder.py:889 interpretation.py:253

corroboration basis (checked in this order):
  no edges or no converged run           → 0.0, "no_evidence"
  ≥2 converged                           → mean(votes / n_algorithms), "algorithm_agreement"
  every edge is prior-required           → 1.0, "prior_determined"          (checked BEFORE stability)
  no edge has bootstrap_stability        → 0.0, "uncorroborated_single_run"
  else                                   → mean stability over beyond-prior edges, "bootstrap_stability"

confidence:
  uncorroborated_single_run → corroboration (i.e. 0.0; self-reported edge confidence may not rescue it)
  prior_determined          → (0.4·edge + 0.2·structure) / 0.6

high-confidence edges: confidence ≥ 0.9 AND not prior-required AND (votes ≥ 2 OR stability ≥ 0.9)

decision:
  confidence ≥ 0.8                  → ACCEPT
  0.5 ≤ confidence < 0.8            → AUGMENT if high-confidence edges ≥ 1 else REVIEW
  confidence < 0.5                  → AUGMENT if high-confidence edges ≥ 1 else REJECT

The manual DAG _construct_dag and atomic confounder placement

    
Nodes: T, Y, every supplied confounder. Edges: any matching KNOWN_CAUSAL_RELATIONSHIPS; T → Y if no path exists; then for each confounder both c → T and c → Y, each acyclicity-guarded. 2.7 Backdoor identification and the adjustment guarantee

  
Backdoor search _find_adjustment_sets, _satisfies_backdoor_criterion

    
Pearl's criterion, checked with NetworkX d-separation on the proper backdoor graph (T's outgoing edges removed): no member may be a descendant of T, and Z must d-separate T and Y. Candidates are all nodes except T, Y, and T's descendants, which excludes colliders and prevents M-bias by construction. Search by increasing size up to 3, return the first non-empty band, at most 3 sets. If no set of size ≤ 3 works, try the full candidate set (with more than 3 independent confounders it is the only admissible set). Only then fall back to [[]]. A degenerate T = Y returns [[]] rather than crashing. graph_builder.py:482 545

  

  
Adjustment guarantee _apply_adjustment_guarantee

    
Every declared covariate (modeled_confounders, else confounders) that is a node of the shipped DAG and not a descendant of T is unioned into every adjustment set. The merged set is not re-checked against the backdoor criterion: declaration wins over DAG evidence by design. The measured reason: tiers-only discovery drops a true confounder from the DAG in 7 of 20 benchmark runs, and this union is what makes those misses harmless. The residual risk (a declared pre-treatment collider whose parents are latent) is assigned to the STRICT adjustment-set policy downstream, with M-bias detection tracked in issue #359. graph_builder.py:614

    
Semantics that estimation depends on
[[]] means a validated-empty backdoor (a randomized or exogenous treatment, estimate unadjusted). [] would mean "no set", which the estimation node treats as None. The two must never be conflated. estimation.py:737

3.2 The dag_source label and discovered confounders

  
The API refuses to call a prior-asserted graph "discovered". It reconstructs exactly the edges the priors imply, using the same anchored-confounder resolution as the builder, and asks whether the shipped DAG has anything beyond them. causal.py:3754

  
prior_edges = {(T, Y)} ∪ {(c, T), (c, Y) for c in anchored (or legacy modeled/confounders)}
beyond      = edges(shipped DAG) − prior_edges

discovery ran, gate == accept, not overridden → "discovered"  if beyond else "prior_asserted"
discovery ran, gate == augment                → "augmented"   if beyond else "prior_asserted"
otherwise                                     → "domain_knowledge"

discovered_confounders = adjustment_sets[0] − everything declared through any channel   (only for discovered/augmented)

  
T and Y are read from the DAG's own node lists rather than the request, because a name divergence would empty the prior set and mislabel every run in the overstating direction. Recorded as ADR-017 (section 4.7).

    4.3 Expert review
    
  
    The human governance surface is a table of reviews keyed by dag_version_hash, a gate object that consults it, an operator-only API, and a React page. Here is how each behaves and when it is reached.
    
  
    When the gate is consulted only on REVIEW or BLOCK bands, and never to stop the run

    4.8 Gaps register
    
  
    Things a reader of this lineage should not assume. Each is verified against the tree, not inferred.
    
  
      
    
    1. REVIEW is rare by design. The band needs a sensitivity WARNING plus both non-critical tests FAILED; 0 of 96 live runs reached it. The enforcement switch (CAUSAL_IMPACT_REQUIRE_DAG_APPROVAL, default off) therefore has no live traffic to act on until an unstable estimate appears. A human rejection, by contrast, halts every band (issue #1971). Infrastructure-absent paths resolve to unavailable, never to a claimed approval (issue #1969).
      2. 
    
    2. Rejection stops re-queueing but does not cascade. A rejected review is durable at the gate (issue #1970). It does not demote a causal_paths row or invalidate an earlier approval on the same hash.
      3. 
    
    3. Approval covers structure, not statistics. The user-facing caveat says so explicitly when an approved DAG meets a REVIEW-band estimate.
      4. 
    
    4. Expiry is never swept. expired is computed at read time from valid_until; nothing writes that status (issue #1972, owner decision).
      5. 
    
    5. Two gates share a word. The discovery gate (accept / augment / review / reject) chooses structure; the refutation gate (proceed / review / block) chooses whether the estimate ships and drives routing. Only the second reaches the human queue.
      6. 
    
    6. discovery_gate_decision == "accept" can accompany a manual DAG. Read discovery_dag_overridden or dag_source, never the gate field alone.
      7. 
    
    7. The hash is narrow by design. Two runs with identical structure but different adjustment sets or confidence share one review key; the separate adjustment_set_hash is the audit channel for that.
      8. 
    
    8. Intentional placeholders, now labelled. forbidden_edges, DiscoveryCache, and CausalGraphSignature carry inline status notes explaining why they exist and what wiring them requires (issue #1973). The vestigial _find_backdoor_paths helper was removed.
      9. 
        
    9. The feature-role system is shadow-mode end to end for this agent. Promotion rules R1–R3, the KG layer, and the LLM decision flag default off; the adjustment-set policy defaults OFF. A caller can now supply role_attributions through the dispatcher (issue #1976), but the API path has no producer.
      10. 
    
    10. The tool-registry discover_dag is guided only on request. Passing treatment_var and outcome_var now reproduces the agent's tiers, required edge, PC-only run, and 20-resample corroboration (issue #1977). Without them it remains the unguided GES + PC ensemble.
      11.
