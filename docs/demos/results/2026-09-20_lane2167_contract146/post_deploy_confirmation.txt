A. THE TRIGGER -- database/** is why this deploy ran at all
----------------------------------------------------------
This is the part that could not be proven before the merge. `git diff --name-only
349858db5 5d0d3c19a` lists 19 paths, in four groups:

    .github/workflows/deploy.yml
    database/migrations/146_drop_legacy_per_hcp_count_columns.sql
    docs/data/... and docs/demos/results/...          (12 files)
    tests/unit/...                                    (5 files)

Matched against the `on.push.paths` globs in .github/workflows/deploy.yml, exactly
ONE of those paths matches ONE glob: database/migrations/146_*.sql against
'database/**' -- the entry added by this very PR (commit 2656eaee3). There is no
'.github/**' glob, no 'tests/**' glob and no 'docs/**' glob in the list.

So the deploy that applied 146 fired ONLY because of the trigger fix shipped in the
same merge. Before 2656eaee3, this merge would have deployed nothing, and 146 would
have sat in database/migrations/ unapplied until some unrelated src/** push carried
it incidentally -- the #1783 failure mode, one layer over, which is the defect
#2167 existed to close. The fix proved itself on its own merge.
