# Codex audit — iteration 18 — issue #1775, PR #1776 (head 8ef2488ae)

## What this branch does

Grounds the causal-analysis clinical-context panel in the SCENARIO being analysed.
Before, the panel showed accurate indication/mechanism/RWE facts that were identical
regardless of which outcome the causal analysis estimated, and for COMMERCIAL levers
it shipped an honest refusal. Now it also returns `analysis_grounding`: verbatim FDA
label considerations selected by relevance to the analysed outcome, plus competitive
framing, plus a note tying them to the commercial question. Zero new upstream calls —
the openFDA label is already fetched for the indications fragment.

## What changed since iteration 17

Both HIGH accepted; both cleared the bar I set.

1. "within the same class" was a FALSE PHARMACOLOGICAL CLAIM for two of three
   curated brands, and the overclaim originated in the `competitor_map` FIELD
   DOCSTRING, which the copy merely repeated. Both fixed: `competitor_map` is keyed
   by disease and every curated entry is an approval in that indication, so the panel
   now says "alternatives approved for the same condition". Nothing is lost — the
   switch risk comes from shared indication, not shared class.
2. The deploy gate could not have caught a dead INITIATION path. Rather than require
   non-empty per (brand, outcome) — wrong, because Rhapsido genuinely has none and
   that would push us to invent some — the expectation is now DERIVED from that
   brand's own live label and must match the deploy EXACTLY. Zero asserted as zero
   where zero is real; Fabhalta's boxed-warning item asserted as present because it
   is real. Plus a control on the expectations themselves, since every assertion in
   the matrix is satisfied by `set() == set()`.

Verified against the deployed pre-fix build: the expectations control PASSES while
every comparison FAILS per brand and per outcome.
